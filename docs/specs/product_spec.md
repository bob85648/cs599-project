# Product Spec: TravelMind 企业差旅多智能体助手

## 1. 背景

企业员工在差旅前需要同时查询制度、住宿标准、报销规则、天气交通、个人偏好和历史行程。信息分散导致人工沟通成本高、答案不一致、上下文难以延续。本项目希望通过 Agentic AI 将这些任务组合成可执行的差旅服务闭环。

## 2. 用户与场景

目标用户：

- 企业员工：希望快速获得差旅制度、行程建议和报销注意事项。
- 行政/财务人员：希望减少重复咨询，提高制度解释一致性。
- 项目评阅者：希望看到 SDD、多智能体、RAG、记忆和评估的完整工程闭环。

典型场景：

1. 用户输入“我要下周从上海去北京出差，预算有限”。
2. 系统识别行程规划、事项收集、偏好管理、制度查询等意图。
3. 协调器并行执行信息收集类 Agent，再调用行程规划 Agent。
4. 系统输出行程建议、住宿/交通提示、制度依据，并将偏好写入长期记忆。

## 3. 功能需求

### FR-1 意图识别

- 识别至少 6 类意图：行程规划、记忆查询、偏好管理、企业知识库问答、联网信息查询、事项收集。
- 支持多意图同时识别。
- 输出结构化 JSON，包含 reasoning、intents、key_entities、rewritten_query、agent_schedule。

### FR-2 智能体编排

- 按 `agent_schedule.priority` 分批执行。
- 同优先级 Agent 并行执行。
- 后续优先级可读取前序结果。
- 聚合所有 Agent 结果为统一响应。

### FR-3 记忆管理

- 保存短期对话上下文。
- 持久化用户偏好、历史行程和对话记录。
- 支持跨会话查询历史偏好与行程。

### FR-4 企业知识库 RAG

- 维护企业差旅制度、报销规则、预订指南、FAQ 等文档。
- 使用本地 embedding 模型向量化文档。
- 返回答案时保留来源线索。

### FR-5 实时信息查询

- 对天气、景点、交通等问题调用联网搜索。
- 搜索结果交给 LLM 摘要。

### FR-6 可靠性治理

- LLM 请求失败时支持有限重试。
- 连续失败触发熔断。
- 提供健康检查入口。

## 4. 非功能需求

- **安全性**：API Key 只能通过环境变量配置，不能硬编码在源码中。
- **可维护性**：子 Agent 以 Skill 插件形式组织，便于新增能力。
- **可测试性**：至少提供记忆、意图识别、RAG、编排、CLI 问答相关测试。
- **可演示性**：CLI 可完成核心闭环，报告中提供截图或录屏。

## 5. 验收标准

- 用户输入差旅需求后，系统能输出结构化行程建议。
- 用户输入偏好后，偏好能被保存并在后续规划中被读取。
- 用户询问差旅制度时，RAG Agent 能返回基于知识库的答案。
- 无真实 API Key 出现在仓库中。
- README 与报告能解释项目如何满足 CS599 技术要素。
